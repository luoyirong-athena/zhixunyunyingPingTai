# 高考志愿服务业务全国 B 端客户运营平台

一个面向全国 B 端志愿规划业务运营人员的客户管理平台 Demo。项目把分散在 Excel、聊天记录和平台主页信息里的客户资料，整理成可采集、可确认、可跟进、可分析的业务工作台。

## 一、项目背景与目标

全国志愿规划业务的客户，主要是志愿规划师、教育机构、生涯规划师和学校等 B 端合作对象。运营人员在实际工作中经常遇到几个问题：

- 客户信息来源分散，需要从抖音、视频号、Excel 或聊天记录中反复复制整理。
- 客户字段格式不统一，姓名、手机号、机构、微信号和地区信息容易缺失或错位。
- 用 Excel 管理客户时，数据密集且缺少状态反馈，难以快速判断客户当前进展。
- 客户销售状态、任务、反馈和聊天记录相互割裂，更新一处后其他地方无法同步。
- 客户反馈和微信沟通记录没有被持续沉淀，难以转化为产品和运营改进建议。

因此，项目目标不是简单替换一张 Excel 表，而是建立一条完整的客户运营链路：

```text
采集客户信息
    ↓
自动拆分字段并进入待确认池
    ↓
人工校验、去重、批量确认
    ↓
客户库统一管理和销售状态变更
    ↓
任务、反馈、聊天记录和经验资料全局联动
    ↓
通过数据分析和客户反馈支持运营决策与产品改进
```

## 三、核心功能与产品设计

### 1. 客户信息采集与字段解析

运营人员可以将一大段客户信息直接粘贴到采集区域，系统通过规则和启发式解析，尝试识别并拆分：

- 姓名、手机号、微信昵称和微信号
- 抖音昵称、抖音号和粉丝量
- 所在省份、城市、客户身份和机构名称
- 来源、备注和其他补充信息

解析结果不会直接写入正式客户库，而是先进入待确认客户池，给运营人员留下人工检查和修改的空间。

### 2. 待确认客户池

待确认客户是采集和客户库之间的审核环节，支持：

- 可视化查看批量导入结果，不需要先下载或拉 Excel。
- 在确认前编辑字段、补充缺失信息和处理重复客户。
- 批量确认，将合格客户加入正式客户库。
- 保留待确认状态，方便运营人员分批处理采集结果。

这个设计将“自动识别”和“人工判断”分开，降低错误字段直接进入客户库的风险。

### 3. 客户库与销售状态全局联动

客户进入正式客户库后，可以随时修改销售状态，例如新客户、已联系、高意向、试用中和已付费等。

同一个客户的数据在多个模块中保持联动：

- 客户列表和客户详情同步更新。
- 首页统计和销售状态分布同步更新。
- 关联任务、反馈和聊天记录继续指向同一个客户。
- 销售状态变更保留操作记录，支持查看历史变化。
- H5 端和网页版共用同一套团队数据。

### 4. 全国区域数据可视化

平台提供全国省份维度的数据展示，运营人员可以从全国范围查看客户分布，再按省份和区域进行筛选，辅助判断：

- 哪些省份客户数量较多。
- 哪些区域处于高意向或已付费阶段。
- 哪些地区需要补充采集或重点跟进。

地图不是独立的装饰组件，而是和客户数据、销售状态及统计结果联动的分析入口。

### 5. 反馈、聊天记录与经验沉淀

平台支持记录客户反馈和微信沟通内容，并将这些信息与客户关联。运营人员可以进一步沉淀：

- 客户常见问题和产品问题。
- 客户对功能、数据和使用体验的反馈。
- 不同销售阶段的沟通话术。
- 客户跟进经验和处理方法。

通过“客户反馈 → 问题归类 → 经验沉淀 → 产品改进”的链路，让客户管理平台同时成为 B 端产品的运营反馈入口。

### 6. 网页版与 H5

- 网页版适合日常批量采集、客户管理和数据分析。
- H5 适合外出沟通、现场查看客户和快速更新销售状态。
- 两端使用同一套后端和团队数据。
- H5 使用独立登录页和移动端布局，不与网页版登录页面混用。

## 四、AI 与自动化能力的实际范围

当前公开 Demo 已在“原始文本 → 客户采集”入口接入 OpenAI 文本解析，并采用规则优先、模型兜底的混合方案：

```text
规则优先识别高确定性字段
    ↓
判断字段完整度和文本歧义
    ↓
复杂文本调用 OpenAI 结构化解析
    ↓
规则结果与 AI 补全结果合并
    ↓
进入待确认客户池，由人工检查后入库
```

当前 AI 解析覆盖姓名、手机号、省份、城市、身份、机构、微信、抖音、视频号和公众号等文本字段。模型通过 OpenAI Responses API 的 JSON Schema 输出，服务端不会把 API 密钥发送到浏览器。

当未配置 `OPENAI_API_KEY`、请求超时或模型输出异常时，系统会自动回退到规则结果，客户仍会进入待确认客户池，不会因为 AI 服务不可用而阻断采集流程。

在 `server/.env` 中配置（可从 `server/.env.example` 开始）：

```bash
OPENAI_API_KEY=your_api_key
OPENAI_CUSTOMER_PARSER_MODEL=gpt-4o-mini
```

当前限制：

- AI 解析目前只处理文本线索，不负责截图 OCR 或图片信息提取。
- 当前版本记录解析策略（规则、AI 或降级），尚未展示字段级置信度和原文证据。
- OpenAI API 调用会产生费用；线上接入真实客户数据前，需要补充脱敏、授权、留存和供应商合规评估。

## 五、项目成果展示

当前 Demo 已形成以下可演示链路：

- 粘贴客户信息并自动拆分字段。
- 对复杂或歧义文本调用 OpenAI，并将结构化结果送入待确认客户池。
- OpenAI 未配置或不可用时自动回退规则解析，采集流程仍可继续。
- 批量导入客户并在待确认池中可视化检查。
- 编辑、去重和批量确认客户。
- 随时修改客户销售状态。
- 在首页、客户详情、任务、反馈和地图中查看联动结果。
- 记录客户反馈和聊天内容，沉淀话术与经验。
- 使用网页版和独立 H5 登录页进入对应工作台。
- 通过虚构演示数据展示完整业务流程。

## 六、项目反思与后续规划

### 已解决的问题

- 将密集的表格数据转成按客户、状态和区域组织的可视化工作台。
- 将客户采集、人工确认和正式入库拆成清晰的分步流程。
- 让销售状态成为客户运营中的共享事实，而不是某一张表里的孤立字段。
- 将客户反馈、聊天记录和经验资料纳入同一套运营闭环。

### 仍可优化的方向

- 增加置信度、证据来源和字段级审核提示。
- 接入截图 OCR，但对敏感信息增加权限控制、脱敏和留存策略。
- 结合客户状态和历史行为，提供下一步跟进建议。
- 基于客户反馈建立问题聚类和产品需求优先级分析。
- 增加真实业务指标埋点，用数据验证采集效率和跟进转化变化。
- 记录人工修正前后结果，建立解析质量评测集和错误类型分析。

## 八、公开仓库与数据说明

- 仓库不包含真实客户数据库、客户证据图片、上传资料和运行日志。
- 所有演示客户、联系方式、账号、聊天记录和业务内容均为虚构数据。
- 当前 Demo 仅用于产品作品展示，不作为生产环境版本使用。
- 项目保留网页版、H5、浏览器插件和核心业务 API，部署配置已从公开版中移除。
